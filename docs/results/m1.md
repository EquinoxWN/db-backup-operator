## A real bug the tests found

The first run failed `TestRunsWalgBackupPushInThePrimaryWhenDue`: the backup ran at 02:00 local
time (UTC+7 on the author's machine), not 02:00 UTC as the API promises, because timestamps read
back from the API are in local time and cron follows the zone of its input. The fix evaluates the
schedule in UTC, and `TestScheduleIsUTCWhateverTheLocalTimeZone` forces a non-UTC local zone so the
bug cannot come back unnoticed on CI machines that happen to run in UTC. Re-applying the bug makes
that test fail.

## Security update (2026-10-10)

govulncheck v1.8.0 with Go 1.26.9 reported 5 newly published advisories in `golang.org/x/net` v0.59.0 (reachable through client-go's HTTP/2 transport, used by `Reconcile` and `podexec`). `golang.org/x/net` was upgraded to v0.60.0; govulncheck then reported no vulnerabilities, and `go build`, `go vet` and `go test ./...` passed (the race detector runs in CI).
